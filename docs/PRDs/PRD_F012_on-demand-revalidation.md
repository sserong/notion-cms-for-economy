# F012 온디맨드 캐시 무효화 PRD

## 핵심 정보

**목적**: 운영자가 Notion DB를 수정한 즉시 사이트에 반영할 수 있도록, ISR 캐시 대기 시간 없이 페이지를 강제 갱신하는 기능 제공
**사용자**: Notion CMS로 콘텐츠를 관리하는 운영자 본인 (1인 블로거)

---

## 사용자 여정

```
1. 운영자가 Notion DB에서 글/종목 등록 또는 수정
   ↓

2. 사이트의 임의 페이지 방문 (홈, 카테고리, 글 상세, 종목 페이지)
   ↓

3. 우측 하단 "최신정보 확인하기" 플로팅 버튼 클릭
   ↓

4. 클라이언트가 /api/revalidate?path=[현재 경로]&secret=[토큰] 호출
   ↓

   [인증 성공 + 캐시 무효화 완료] → 성공 토스트 표시 → 페이지 자동 새로고침
   [인증 실패 (토큰 불일치)]       → 실패 토스트 표시 → 현재 페이지 유지
   [네트워크/서버 오류]            → 오류 토스트 표시 → 현재 페이지 유지
   ↓

5. 새로고침 완료 → Notion DB의 최신 콘텐츠가 화면에 반영됨
```

## 페이지별 상세 기능

### 온디맨드 캐시 무효화 API (`/api/revalidate`)

> **구현 기능:** `F012` | **인증:** REVALIDATE_SECRET 토큰 필수

| 항목            | 내용                                                                                                                                                                                                                                                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **역할**        | 클라이언트로부터 경로와 비밀 토큰을 받아 ISR 캐시를 즉시 무효화하는 서버 전용 API 엔드포인트                                                                                                                                                                                                                                |
| **진입 경로**   | 최신정보 확인하기 버튼 컴포넌트(F013)의 fetch 호출 — 직접 브라우저 접근 불가                                                                                                                                                                                                                                                |
| **사용자 행동** | 직접 사용자 조작 없음 (버튼 클릭 시 컴포넌트가 자동 호출)                                                                                                                                                                                                                                                                   |
| **주요 기능**   | - 쿼리 파라미터 `secret` 값과 서버 환경 변수 `REVALIDATE_SECRET` 비교 — 불일치 시 HTTP 401 반환 (F012)<br>- 쿼리 파라미터 `path` 값 유효성 검사 — 누락 시 HTTP 400 반환 (F012)<br>- `revalidatePath(path)` 실행으로 해당 경로의 ISR 캐시 즉시 무효화 (F012)<br>- 성공 시 HTTP 200과 `{ revalidated: true, path }` JSON 반환 |
| **다음 이동**   | 성공 응답 수신 → 버튼 컴포넌트가 `window.location.reload()` 실행, 실패 응답 수신 → 버튼 컴포넌트가 오류 토스트 표시                                                                                                                                                                                                         |

### 구현 참고

```ts
// app/api/revalidate/route.ts 핵심 로직
import { revalidatePath } from 'next/cache'
import { NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const secret = request.nextUrl.searchParams.get('secret')
  const path = request.nextUrl.searchParams.get('path')

  if (secret !== process.env.REVALIDATE_SECRET) {
    return Response.json({ message: '인증 실패' }, { status: 401 })
  }
  if (!path) {
    return Response.json({ message: 'path 파라미터 누락' }, { status: 400 })
  }

  revalidatePath(path)
  return Response.json({ revalidated: true, path })
}
```

> 비밀 토큰은 절대 클라이언트 코드에 하드코딩하지 않습니다.
> `REVALIDATE_SECRET`은 서버 전용 환경 변수로 관리하고, 버튼 컴포넌트는 Next.js API Route를 경유하여 호출합니다.
